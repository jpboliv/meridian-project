# Roadmap

GitHub [milestones](https://github.com/jpboliv/meridian-agents/milestones) group work by outcome. Use issues for tasks and Markdown for the agreed behavior. Revise this guide when a decision changes the scope.

| Milestone | Issues | Evidence needed to finish |
|---|---|---|
| [0: Design foundation](https://github.com/jpboliv/meridian-agents/milestone/1) | 1–11 | The owner can explain the shift sequence, information boundaries, comparison method, and agreed contracts. |
| [1: First-line agent](https://github.com/jpboliv/meridian-agents/milestone/2) | 12–13 | One agent correlates sources through MCP, acts within its limits, and reports observed recovery or missing evidence. Save a baseline and tag M1. |
| [2: Memory-aware on-call agent](https://github.com/jpboliv/meridian-agents/milestone/3) | 14–17 | Show useful recall, correction after a change, isolated access, and measured cache behavior. Compare with M1 and tag M2. |
| [3: Coordinated response](https://github.com/jpboliv/meridian-agents/milestone/4) | 18–19 | Specialists share evidence, detect a failed handoff, and resume after an interruption with exactly one effect. Tag M3. |
| [4: Delivery](https://github.com/jpboliv/meridian-agents/milestone/5) | 20 | Reproduce results from a clean clone. Present a verified fix, a controlled failure, and a resumed action by 30 November 2026 at 23:59 Lisbon time (`Europe/Lisbon`). |

Start with goals and the reference incident. Agree on each contract before its implementation begins. Later design issues can remain open while earlier work proceeds. Record each experiment at the milestone where it runs.
