Offline follow-up (23 November). The owner approved an offline follow-up to the baseline failures. The harness changes shipped in `gateway-m1.7`. See the [experiment record](projects/course-02-agentic-ai/docs/experiments.md#2026-11-23-offline-follow-up-to-the-baseline-failures-gateway-m17). Before any change, isolation was checked from inside the tuning environment: a public case loaded, and the owner's home directory, both evaluator-store locations, the manifest and `.env` were absent.
- **Limits.** Unchanged: 6 requests, 512 output tokens, one repair. Graders, fixtures and all earlier traces are also unchanged.
- **E.** While samples are stale, a refresh in which no previously stale replica gets a newer sample time ends the model's reads. One replica advancing is progress, even if another stays stale. The cited link evidence comes from after the stall: the model's own new link read, or else one harness read that replaces any earlier link read. If that read fails, no link is cited and the link state is reported unknown. It hands over one faulty link with its source, or names the gap with no fault claim. The report marks this as a harness decision (`stale_evidence`).
- **D.** A link handover target must exactly match an observed down or degraded link. Otherwise the one repair is used, then a safe handover.
- **A2.** `progress.restart_supported` comes from the same predicate as the restart gate. Approval, receipt and recovery gates are unchanged.
- **A3.** `model_failure` is one of `output_limit`, `validation_exhausted`, `provider_error` or `unknown`, from bounded per-attempt response signals. An explicit output limit on the decision's last response is definitive; a truncated first reply followed by an ambiguous invalid one stays `unknown`. Slot 11 (historical A3) stays `unknown`.
- **Offline evidence.** On the mock wire, the saved E choices stop after 3 requests and pass 11/11. The saved D3 decorated target, then a valid one, passes 11/11. The saved A2 choices still reach the cap and fail overall, with 7 of 12 checks passed; they are fixed choices, not model evidence. Changed-fixture controls show the E handover uses only link reads from after the stall: a fault that cleared at tick 70 is not cited, one that started at tick 70 is, and a failed fresh read cites no link.
- **Review fix.** A fresh Opus review found one Medium: the E stall handover could cite a link read from before the stalled refresh. Fixed as above, with no extra model decision; isolation was re-checked from the tuning shell first. The m1.7 scripted traces were regenerated (only the `shift.py` hash changed).
